# 本地运行环境分析与启动步骤

> 日期:2026-11-02
> 场景:从零开始在 Windows 上拉起 chatbox 开发环境

## 一、环境需求 vs 本地现状

| 依赖 | 要求 | 本地 | 状态 |
|---|---|---|---|
| Node | `>=22.13.0 <23.0.0`(`engines.node`) | v22.17.0 | ✅ 满足 |
| pnpm | `>=10.17.0`,`packageManager` 钉死 `pnpm@10.33.0`(含 sha512 校验) | 未安装 → 已通过 corepack 激活 | ✅ 已解决 |
| git | 非硬性 | v2.32.0.windows.1 | ✅ 可用 |
| npm | 非硬性 | v10.9.2 | ✅ 可用 |
| corepack | 非硬性,用于激活 pnpm | v0.33.0 | ✅ 可用 |

### 关键约束

- **Node 版本卡死在 22.x**:不能升到 23,否则 `engine-strict=true` 会直接拦截 `pnpm install`。
- **pnpm 版本被锁定**:`package.json` 的 `packageManager` 字段钉死 `pnpm@10.33.0`,不能随便用别的版本。正确方式是 corepack,不要 `npm i -g pnpm`。
- **必须是 pnpm**:仓库是 pnpm workspace(有 `@chatbox/core`、`@chatbox/react`、`@chatbox/i18n` 等 `workspace:*` 包),用 npm/yarn 会导致 workspace 链接失败。
- **Windows 原生模块**:依赖里有 `@electron/rebuild`、`@libsql/client`、`@anthropic-ai/sandbox-runtime`,`postinstall` 会跑 `electron-rebuild` 重编译 electron 原生模块。如遇 `gyp`/`MSBuild` 错误,需补 VS Build Tools(C++)+ Python 3;预编译二进制够用时不需要。

## 二、依赖安装路径

`pnpm install` 涉及三处位置:

1. **全局缓存(共享)**:`G:\.pnpm-store\v10` — 所有 pnpm 项目复用,不污染项目目录。
2. **项目本地**:`G:\Workspaces\node-project\chatbox\node_modules\` — `.npmrc` 配了 `node-linker=hoisted`,结构同 npm 扁平化。
3. **workspace 子包**:`packages\<各包>\node_modules\`、`release\app\node_modules\`(原生依赖在此)。

`.npmrc` 关键项:
- `node-linker=hoisted` — 扁平化 node_modules(electron 兼容)。
- `auto-install-peers=true` — 自动装 peer。
- `node-options=--max-old-space-size=5120` — 给 Node 5GB 内存。
- `update-notifier=false`、`engine-strict=true`。

## 三、镜像配置(国内网络)

直连 `registry.npmjs.org` 会 TLS 重置(`ECONNRESET`),corepack 下载 pnpm 和 pnpm 拉依赖都走不通。

### 已执行的配置

1. **corepack 激活 pnpm**(临时环境变量,不持久):
   ```bash
   export COREPACK_NPM_REGISTRY=https://registry.npmmirror.com
   corepack prepare pnpm@10.33.0 --activate
   ```
   只影响 corepack 下载 pnpm 自身,不改动全局 npm registry。pnpm 激活后不再需要此变量。

2. **pnpm 用户级 registry**(持久):
   ```bash
   pnpm config set registry https://registry.npmmirror.com --location=user
   ```
   写入 pnpm 用户 config,所有 pnpm 项目默认走淘宝镜像。

## 四、启动命令

### 最小可运行路径

```bash
corepack enable && corepack prepare pnpm@10.33.0 --activate   # 已完成
pnpm install                                                    # 进行中
pnpm dev                                                        # 待执行
```

### 常用脚本(package.json scripts)

| 命令 | 用途 |
|---|---|
| `pnpm dev` | 标准 Electron 开发(= `pnpm start` = `electron-vite dev`) |
| `pnpm dev:local` | 走本地 API(`USE_LOCAL_API=true`) |
| `pnpm dev:web` | 只跑 Web 版(`DEV_WEB_ONLY=true`) |
| `pnpm dev:debug` | 主进程带 `--inspect=5858` 调试 |
| `pnpm build` | 构建 main/preload/renderer 产物 |
| `pnpm build:web` | 构建 Web 版 |
| `pnpm package` | 打可分发安装包(Windows) |
| `pnpm test` | vitest 单测 |
| `pnpm check` | TS 类型检查 + 生成路由/worker |
| `pnpm lint` / `pnpm lint:fix` | biome lint |
| `pnpm format` | biome format |
| `pnpm storybook` | Storybook 开发 |

### electron-builder 打包变体

- `pnpm electron:publish-win` — Windows 发布
- `pnpm electron:publish-mac` — macOS 发布
- `pnpm electron:publish-linux` — Linux 发布
- `pnpm package:all` — 三平台同时打包

## 五、本次实际执行的操作记录

1. 分析 `package.json` 的 `engines`、`packageManager`、`scripts`、依赖结构。
2. 检测本地 Node/pnpm/npm/corepack/git 版本,确认只缺 pnpm。
3. `corepack enable` → 直连 npmjs 失败(`ECONNRESET`)。
4. 改用 `COREPACK_NPM_REGISTRY=https://registry.npmmirror.com` 重试,成功激活 pnpm@10.33.0。
5. `pnpm config set registry https://registry.npmmirror.com --location=user` 持久化镜像。
6. 确认 `.npmrc` 配置(hoisted、engine-strict、max-old-space-size)。
7. 执行 `pnpm install`,exit 0,无报错。workspace 包 core/i18n/react 三个链接成功;根 node_modules 共 1740 个包,electron/electron-vite/vitest 二进制就位;postinstall 检测到 11 个原生模块(electron、sharp、@parcel/watcher、rollup win32 二进制等)已处理。`release/app/node_modules` 不存在——符合 pnpm hoisted 预期(`ensure-app-deps` 仅在打包阶段生成)。
8. 执行 `pnpm dev`(electron-vite dev)。编译产物:主进程 → `out/main/main.js` + `main.js.map`(7.4M/13.9M);preload → `out/preload/index.js` + `index.js.map`(2.8K/5.3K);renderer 不落盘,由 Vite dev server(端口 1212)在内存 serve。Electron 窗口正常启动,日志显示 session row migration(11 candidates,0 migrated)、OAuth flow 取消等正常运行信息。
9. 用户手动停止 `pnpm dev`。

## 六、dev 模式产物说明

| 产物 | 路径 | 说明 |
|---|---|---|
| 主进程 | `out/main/main.js` + `main.js.map` | electron-vite dev 编译,`package.json` 的 `"main": "out/main/main.js"` 指向这里 |
| preload | `out/preload/index.js` + `index.js.map` | preload 脚本 |
| renderer | **内存/Vite dev server(1212)**,磁盘不落盘 | 仅 `pnpm build` 时才写 `release/app/dist/renderer/` |
| Vite 依赖优化缓存 | `node_modules/.vite/` | renderer dev |
| 生成的路由树 | `src/renderer/routeTree.gen.ts` | dev/build 时生成的源码(会 git diff) |

对比:dev 模式 → `out/` + 内存;production build(`pnpm build`) → `release/app/dist/{main,preload,renderer}/`。
